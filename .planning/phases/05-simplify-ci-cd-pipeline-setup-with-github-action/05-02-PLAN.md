    **Replace the deploymentSetupGuide.hbs partial** to show the consolidated workflow snippet. The new snippet should be approximately:

    ```yaml
    name: Deploy

    on:
      workflow_dispatch:
        inputs:
          environment:
            description: "Environment to deploy to"
            required: true
            type: choice
            options:
              - staging    # ({{#each environments}}...{{/each}} dynamic)
              - prod
          buildId:
            description: "Build ID (commit SHA)"
            required: false
            type: string
      workflow_call:
        inputs:
          environment:
            required: true
            type: string
          buildId:
            required: false
            type: string

    jobs:
      deploy:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
            with:
              ref: ${{ inputs.buildId || github.sha }}

          - name: GitLaunch Deploy
            uses: donedgardo/build-reporter@v1
            with:
              api-key: ${{ secrets.GITLAUNCH_API_KEY }}
              service-id: ${{ vars.GITLAUNCH_SERVICE_ID }}
              environment: ${{ inputs.environment }}
              build-id: ${{ inputs.buildId || github.sha }}

          ####################################
          # Add your deployment steps here  #
          ####################################
          - name: Deploy
            run: echo "Deploy to ${{ inputs.environment }}"
    ```

    Key changes from current template:
    1. Remove all four separate `donedgardo/build-reporter@v1` steps (deploying, deployed, error, cancelled)
    2. Replace with single `GitLaunch Deploy` step (no `action:` or `status:` inputs)
    3. Remove `serviceId` from workflow_dispatch inputs (now via vars.GITLAUNCH_SERVICE_ID only)
    4. Remove `env:` block (ENVIRONMENT, BUILD_ID, SERVICE_ID) — use `inputs.*` directly
    5. Remove `secrets:` section from workflow_call (action reads secret directly)
    6. Keep `{{#each environments}}` Handlebars loop for environment options
    7. Update the `copyDeployWorkflow()` JavaScript function to copy the new shorter text
    8. Keep the "Auto-deploy from CI" tip section but simplify the reusable workflow call (remove `serviceId` and `secrets: inherit` since service-id comes from vars)
    9. Keep the "Deployment Status Values" reference section

    Use HTML entities for curly braces in the template (&#123;&#123; and &#125;&#125;) as the current template does, to prevent Handlebars from interpreting GitHub Actions expressions.

    **Update created.hbs:**
    Replace the Step 2 partial inclusion. Instead of `{{> buildReportingInstructions ...}}` which shows the CI build-report step, replace it with `{{> deploymentSetupGuide ...}}` to show the consolidated deploy workflow. This gives new users the primary workflow they need. Renumber the steps:

    The `buildReportingInstructions.hbs` partial itself is NOT modified — it still works for users who want a separate CI build-reporting step. It's just not the primary onboarding instruction anymore.

    **NOTE:** `src/server/routes/services/settings.ts` does NOT need changes. It already passes `service.id`, `serviceId`, and `environments` to the template context, which is everything the consolidated snippet needs.
