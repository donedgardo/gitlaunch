Add environment limit checking to PlanEnforcementService using TDD.

<feature>
  <name>Environment limit enforcement in PlanEnforcementService</name>
  <files>

    src/services/billing/planEnforcementService.test.ts
  </files>
  <behavior>
    canAddEnvironment(accountId, serviceId) checks whether a service can add another environment:
    - Loads the account to get planLimits.maxEnvironments
    - Loads the service to count current environments (service.environments.length)
    - Returns { allowed: true } if current count < maxEnvironments
    - Returns { allowed: false, reason: "Environment limit reached (2/2). Upgrade to add more environments.", upgradeRequired: true } when at limit

    Tier limits for maxEnvironments:
    - Free: 2 (staging + prod are defaults, cannot add more)
    - Pro: 10
    - Team: 999

    enforceEnvironmentLimit(accountId, serviceId) throws PlanLimitError when limit exceeded.

    Cases:
    - Free account with 2 environments -> canAddEnvironment returns { allowed: false }
    - Free account with 1 environment -> canAddEnvironment returns { allowed: true }
    - Pro account with 9 environments -> canAddEnvironment returns { allowed: true }
    - Pro account with 10 environments -> canAddEnvironment returns { allowed: false }
    - Team account with 50 environments -> canAddEnvironment returns { allowed: true }
    - Non-existent account -> canAddEnvironment returns { allowed: false, reason: "Account not found" }
    - Non-existent service -> canAddEnvironment returns { allowed: false, reason: "Service not found" }

  </behavior>
  <implementation>
    1. Add `maxEnvironments: number` to PlanLimits type in accountRepository.ts
    2. Update FREE_PLAN_LIMITS to include maxEnvironments: 2
    3. Update PRO_PLAN_LIMITS to include maxEnvironments: 10
    4. Update TEAM_PLAN_LIMITS to include maxEnvironments: 999
    5. Add `canAddEnvironment(accountId: ObjectId, serviceId: ObjectId): Promise<LimitCheckResult>` to PlanEnforcementService
       - Loads account (returns not-found if missing)
       - Loads service from serviceRepo.findById(serviceId) (returns not-found if missing or different account)
       - Compares service.environments.length against account.planLimits.maxEnvironments
    6. Add `enforceEnvironmentLimit(accountId: ObjectId, serviceId: ObjectId): Promise<void>` that throws PlanLimitError when limit exceeded
    7. Add `environments` section to UsageInfo type and getUsage method (current count from service, limit from planLimits) — SKIP this. Environment usage is per-service, not per-account like other resources. getUsage stays account-level.
  </implementation>
</feature>
