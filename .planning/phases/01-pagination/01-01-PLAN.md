<feature>
  <name>BuildRepository.findPaginated</name>
  <files>src/repositories/buildRepository.ts, src/repositories/buildRepository.test.ts</files>
  <behavior>
    Method signature: findPaginated(accountId: ObjectId, serviceId: ObjectId, page: number, limit: number): Promise&lt;{ builds: Build[]; total: number; hasMore: boolean }&gt;

    Cases:
    - (accountId, serviceId, 1, 10) with 25 builds -> { builds: [newest 10], total: 25, hasMore: true }
    - (accountId, serviceId, 2, 10) with 25 builds -> { builds: [next 10], total: 25, hasMore: true }
    - (accountId, serviceId, 3, 10) with 25 builds -> { builds: [last 5], total: 25, hasMore: false }
    - (accountId, serviceId, 10, 10) with 5 builds -> { builds: [], total: 5, hasMore: false }
    - (accountId, serviceId, 1, 10) with 0 builds -> { builds: [], total: 0, hasMore: false }
    - (accountA, serviceId, 1, 10) should NOT return accountB's builds (tenant isolation)
    - (accountId, serviceId, 0, 10) should behave as page 1 (input sanitization)
    - (accountId, serviceId, -1, 10) should behave as page 1 (input sanitization)

    Builds sorted by createdAt descending (newest first), matching existing findByAccountAndService pattern.
    Uses existing compound index: { accountId: 1, serviceId: 1, createdAt: -1 }.
    Uses Promise.all for parallel skip/limit query + countDocuments for efficiency.

  </behavior>
  <implementation>
    Add findPaginated method to BuildRepository class:
    1. Sanitize inputs: page = Math.max(1, Math.floor(page)), limit = Math.max(1, Math.min(100, Math.floor(limit)))
    2. Calculate skip = (page - 1) * limit
    3. Run Promise.all with two queries:
       a. collection.find({ accountId, serviceId }).sort({ createdAt: -1 }).skip(skip).limit(limit).toArray()
       b. collection.countDocuments({ accountId, serviceId })
    4. Return { builds, total, hasMore: skip + builds.length < total }

    Export PaginatedResult type: { builds: Build[]; total: number; hasMore: boolean }

    Follow existing test patterns in buildRepository.test.ts:
    - MongoMemoryServer setup/teardown
    - Given/When/Then style with behavior-focused assertions
    - Use small delays between creates to ensure distinct timestamps for sort order tests
    - DO NOT mock MongoDB internals -- use real MongoMemoryServer

  </implementation>
</feature>
