Add a plan picker step to the onboarding flow so new users select Free/Pro/Team before accessing the dashboard. No payment is collected — plan selection simply records the chosen plan on the account.

Purpose: Users must explicitly choose a plan (PLAN-01). This creates intentional commitment and sets up correct plan limits from the start. Free users get Free limits, Pro/Team users get their tier's limits (trial period handled in Phase 4).

Output: Plan selection template, onboarding routes, updated auth redirect flow.

  <action>
    **Step 1: Create plan-selection.hbs template**

    Create `src/templates/onboarding/plan-selection.hbs` with a 3-column grid (responsive: 1-col mobile, 3-col desktop) showing:

    - **Free** ($0/mo): 3 public repositories, 3 services, 1 team member. Button: "Continue with Free". Form posts to `/onboarding/select-plan` with `plan=free`.
    - **Pro** ($19/mo, highlighted/recommended): 10 repos (public + private), 10 services, 5 team members. Button: "Start with Pro". Form posts to `/onboarding/select-plan` with `plan=pro`.
    - **Team** ($49/mo): Unlimited repos, unlimited services, unlimited team members, priority support. Button: "Start with Team". Form posts to `/onboarding/select-plan` with `plan=team`.

    Follow the existing template patterns (use layout `/layouts/main.hbs`, Tailwind CSS classes). Style the Pro card with a "Most Popular" badge and distinct background (blue-600) to highlight it. Use check-mark SVG icons for feature lists (same pattern as landing page index.hbs).

    All three forms use standard HTML form POST (not HTMX), since this is a full-page navigation step in onboarding.

    **Step 2: Add onboarding routes**

    In `src/server/routes/onboarding/index.ts`, add two new routes:

    1. **GET /onboarding/plan-selection**: Render plan-selection.hbs template. Require authentication (redirect to `/auth/github` if no session). If account already has a non-Free plan set (returning user), redirect to `/onboarding` (GitHub App install step).

    2. **POST /onboarding/select-plan**: Accept `{ plan: string }` body. Validate plan is "free", "pro", or "team". Update the account's plan and planLimits by calling the existing `accountRepository.selectPlan(account._id, plan as Plan)` method (created in Plan 02-01 Task 1). This method sets plan and planLimits WITHOUT touching stripeCustomerId/subscriptionId, and works for all plans including Free.

       After setting plan, redirect to `/onboarding` (GitHub App install step, which then goes to repo selection and dashboard).

    The `OnboardingRoutesDeps` type needs `accountRepository` (already there).

    **Step 3: Update auth redirect**

    In `src/server/routes/auth/github.ts`, update the new-user redirect:
    - Currently: new users -> `/onboarding`
    - Change to: new users -> `/onboarding/plan-selection`

    This way the flow becomes: signup -> plan selection -> GitHub App install -> repo selection -> dashboard.

    Returning users (already have account with GitHub App) still go to `/dashboard`.

    **Step 4: Write/update tests**

    In onboarding route tests:
    - Test GET /onboarding/plan-selection renders template for authenticated users
    - Test POST /onboarding/select-plan with plan=free sets Free plan and redirects to /onboarding
    - Test POST /onboarding/select-plan with plan=pro sets Pro plan and redirects to /onboarding
    - Test POST /onboarding/select-plan with invalid plan returns error

    In auth tests:
    - Update existing test that checks new user redirect to expect `/onboarding/plan-selection` instead of `/onboarding`
