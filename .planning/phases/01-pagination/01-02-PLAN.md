<feature>
  <name>Dashboard route ?page=N pagination</name>
  <files>src/server/dashboard/index.ts, src/server/dashboard/index.test.ts</files>
  <behavior>
    Route: GET /dashboard/:serviceName?page=N

    Cases:
    - GET /dashboard/my-service -> loads page 1 (default), passes pagination to template
    - GET /dashboard/my-service?page=2 -> loads page 2, pagination.hasPrev=true
    - GET /dashboard/my-service?page=1 -> first page, pagination.hasPrev=false
    - GET /dashboard/my-service with 25 builds, page=1 -> shows 20 builds, pagination.hasMore=true, totalPages=2
    - GET /dashboard/my-service with 25 builds, page=2 -> shows 5 builds, pagination.hasMore=false
    - GET /dashboard/my-service with 0 builds -> shows empty state (same as current behavior)
    - HTMX request (hx-request header) -> returns partial with same pagination data

    Page size: 20 (constant DEFAULT_PAGE_SIZE = 20)

    Pagination metadata passed to template:
    {
      currentPage: number,
      totalPages: number,
      hasMore: boolean,
      hasPrev: boolean
    }

  </behavior>
  <implementation>
    1. Add Fastify querystring schema to GET /dashboard/:serviceName route:
       - Update generic type to include Querystring: { page?: number }
       - Add schema.querystring with page as integer, minimum 1, default 1
       - Note: Fastify uses "querystring" (not "query") in schema definitions

    2. Replace buildRepository.findByAccountAndService() call with buildRepository.findPaginated():
       - Extract page from req.query.page (defaults to 1 via schema)
       - Define DEFAULT_PAGE_SIZE = 20 as constant at top of file
       - Call findPaginated(accountId, activeService._id, page, DEFAULT_PAGE_SIZE)
       - Destructure { builds, total, hasMore }

    3. Compute pagination metadata:
       - currentPage: page
       - totalPages: Math.ceil(total / DEFAULT_PAGE_SIZE)
       - hasMore: from findPaginated result
       - hasPrev: page > 1

    4. Pass pagination object to both full-page and HTMX partial reply.view() calls:
       - Add pagination: { currentPage, totalPages, hasMore, hasPrev } to template data
       - Also pass serviceName to pagination for URL construction

    5. Keep needsDeploymentSetup logic working -- it currently checks builds.length.
       After pagination, use total > 0 instead of builds.length > 0 for the check,
       since builds may be empty on later pages but builds still exist.

    Follow existing test patterns in dashboard/index.test.ts:
    - Fastify inject() with query parameters
    - Create enough test builds to span multiple pages
    - Verify response body contains pagination data
    - Test both full-page and HTMX partial (hx-request header) responses
    - DO NOT test template rendering details -- test that pagination data is passed correctly

  </implementation>
</feature>
