# GitLaunch Agent Skills

Skills a customer's coding agent reads to integrate their repository with
GitLaunch. They are written for the _customer's_ repo, not this one — nothing
here is loaded when working on GitLaunch itself.

## Skills

| Skill                  | Purpose                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------- |
| `gitlaunch-onboarding` | Detect a project and its CI/CD, then open a PR wiring up build reporting and deploy control |

## How customers get them

Served as static files by the instance itself. `registerPlugins.ts` mounts this
directory at `/skills`, so the live copy is always the one matching that
deployment:

```
https://gitlaunch.dev/skills/gitlaunch-onboarding/SKILL.md
https://gitlaunch.dev/skills/gitlaunch-onboarding/references/detection.md
```

Onboarding step 2 renders a copy-paste prompt pointing at that URL with the
service ID and freshly minted API key already filled in
(`src/templates/partials/aiAgentSetup.hbs`). The user pastes it into Claude Code,
Cursor, or anything else that reads a repo — no install step, and a self-hosted
instance serves the skill version that matches its own API.

The `Dockerfile` copies this directory into the production image; it is not part
of the compiled `dist/`.

## Keeping snippets from drifting

Skills must **not** carry their own copy of the workflow YAML. The canonical
snippets come from the API at runtime:

```
GET /api/v1/services/:serviceId/setup-snippets     # scope: services:read
```

They are generated by `src/services/setup/setupSnippets.ts`, which is the single
source of truth, and templated with the service's real environments. Two
contracts are pinned by tests in `setupSnippets.test.ts`:

1. The deploy workflow declares exactly the inputs `MultiTenantGithubDispatchService`
   dispatches (`environment`, `buildId`) — GitHub 422s the whole dispatch otherwise.
2. Reported statuses come from the golden reporter contract shared with the
   `github-action` submodule.

If you change the YAML, change it there. `src/tests/skillsServed.test.ts` checks
that every `references/` file a skill names actually exists and that no skill
carries something shaped like a live API key.

## Editing a skill

Keep `SKILL.md` short and put detail in `references/`. Agents load the skill body
eagerly and reference files on demand, so the body should be decision-making —
which case am I in, what must I never do — and references should hold the lookup
tables.
