<objective>
Extract a pure `planDispatch` function that computes a provider-agnostic dispatch plan from already-resolved inputs (no DB, no HTTP). It returns a `GitHubDispatchPlan` (discriminated union member `kind: "github"`) on success, or a `ValidationError` when the GitHub installation is missing. This is the functional core for PROV-02 (dispatch computed as a provider-agnostic plan).

Purpose: PROV-02 requires dispatch to be computed as a provider-agnostic plan that the GitHub path runs through with no observable behavior change. Plan 02 builds and unit-tests the pure `planDispatch` function; Plan 03 (Wave 2) wires `BuildDispatchService` through it. Splitting the pure core from the integration keeps each within budget and lets the pure module be TDD'd without mocks.

Output: `src/services/dispatch/planDispatch.ts` (pure) and `src/services/dispatch/planDispatch.test.ts` (no-mock tests), green under `yarn test`.

**Scope boundary:** This plan does NOT modify `BuildDispatchService` (that is Plan 03) and does NOT touch `github-action/` (hard package boundary). The pure/impure line: DB null-checks for account/service/repo STAY in `BuildDispatchService`; `planDispatch` only validates its resolved inputs (installationId non-falsy) and shapes the plan. The `DispatchPlan` union is deliberately GitHub-only now — a Jenkins member is added in Phase 9.
</objective>
